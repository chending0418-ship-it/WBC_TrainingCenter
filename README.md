# WBC Training Center

面向单一线下训练场馆的微信小程序。家长可以查看排课，为账户关联的一名孩子预约团课或私教，并查询预约和积分流水。教练只读查看自己的日程和所授课程的孩子姓名。管理员通过密码进入同一小程序的管理端，维护排课、预约和积分。

## 当前状态

本地 MVP 已实现孩子和联系人资料、未来 30 天排课、预约申请和管理员确认、积分余额和流水。微信开发者工具使用游客 AppID，登录页提供三种本地演示身份，登录后只显示该角色的页面。管理端支持课程类型、教练、周期模板、家长搜索、预约确认和取消，以及线下积分入账、调整和冲正。教练端可查看本人今天和本周的授课日程。正式微信登录属于后续开发阶段。

## 本地启动

需要 Node.js 24、npm 和微信开发者工具。在仓库根目录执行以下命令。

```sh
npm ci
npm run build:miniapp
npm run dev:api
```

API 默认启动在 `http://127.0.0.1:3000`，可访问 `/health` 检查。SQLite 文件默认位于 `apps/api/data/wbc.sqlite`，首次启动自动生成演示账户和排课。如需一份新的演示数据，可以给 API 指定新的 `WBC_DB_PATH`，例如 `WBC_DB_PATH=/tmp/wbc-fresh-demo.sqlite npm run dev:api`。

在微信开发者工具的「小程序 → 导入」选择 `apps/miniapp`，使用项目自带的 `touristappid` 和「不使用云服务」，随后编译。小程序的 TypeScript 和静态文件由 `npm run build:miniapp` 输出到 `dist/`。修改源码后重新执行构建并在工具里编译。

### 验证家长端

在登录页点「家长登录」。家长端只显示「课表」「我的预约」「我的账户」。切换身份时，在「我的账户」退出，回到登录页。

1. 在「课表」选择未开课的团课或私教时段，查看积分报价并提交申请。
2. 在「我的预约」查看待确认状态，在「我的账户」查看预留积分。管理员确认后才扣积分；拒绝或过期会释放预留。
3. 如需取消已确认的预约，请在开课前至少 6 小时联系管理员。管理员取消后会释放名额，带课程类型的班次按设置自动退积分；去「我的账户」查看退回流水。

退积分按原预约扣减计算，部分退还向下取整。比例为 0、未选类型或自由预约的私教时段不自动退积分。团课班次积分由管理员设置，私教本地按教练配置的每 30 分钟积分累计。首次预约前补齐孩子的姓名或昵称、出生年月和性别。「我的账户」还可选填联系人、查看演示协议和隐私说明。模拟登录服务仅供本机开发。

### 验证本地管理端

在登录页选择「管理员登录」，默认演示密码为 `wbc-demo-2026`。如需使用自定本地密码，在启动 API 时设置 `WBC_ADMIN_PASSWORD`。旧版演示库会在 API 启动时自动升级并保留已有预约和流水。

1. 在「课程类型」新增类型，填写名称、每位教练最多带几名学员和取消退还比例。全额退还为 100%，不退还填 0。随后在「排课管理」新增或编辑班次时选择类型，容量不能超过类型的人数上限。也可按周多选日期、同一天安排多个时段。退出管理员身份后以家长登录，在「课表」核对课程出现。私教可按教练和星期设置开放时间，也可按日期新增停用时段。
2. 在管理首页查看「待确认预约」，确认或拒绝家长申请。也可在「预约管理」直接代约。选择至少 6 小时后开始的班次做取消测试，核对名额释放、退回积分和操作来源。
3. 在「积分管理」选择家长账户。线下入账需填积分、原因和凭证号或备注。人工调整可以增加或扣减可用积分，可关联本账户的一笔预约。家长端「我的账户」刷新后应看到新余额和流水。
4. 在线下入账或人工调整的流水旁点「冲正」，填写原因后确认。系统按原流水的反向金额新增一笔记录，两条流水互相可查。每笔最多冲正一次，调整或冲正后的余额须大于或等于零。

5. 在「教练管理」新增、编辑或停用教练；有未结束预约的教练需要先处理预约。到「排课管理 → 周期模板」编辑或停用模板，核对已预约、单独调整的班次保留。在「家长资料」可搜索孩子姓名、联系人、电话或账户 ID。

### 验证本地教练端

在登录页点「教练登录」，选择一名已启用的演示教练，查看「今天」和「本周」。先提交一笔对应教练的预约并由管理员确认，再以该教练登录，核对预约人数和孩子姓名。退出后再登录另一名教练，核对只显示该教练自己的日程。

集成测试使用独立 SQLite，覆盖团课并发容量、私教时段冲突、积分原子扣减、幂等重试、取消、账户隔离、跨年排课、管理员权限、周期排课、代约、冲正、教练数据隔离，以及两个 SQLite 连接并发写入同一账户。

## 提交流程

每次变更都从最新的 `main` 新建分支，完成检查后推送分支并向 `main` 提交 Pull Request。通过 PR 合并后，将本地 `main` 同步到 `origin/main`。禁止直接推送 `main`。
